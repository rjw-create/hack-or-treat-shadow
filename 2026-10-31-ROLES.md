# Roles: Shadow (Gemma 4 entry)

Several Claude sessions work on this repo at once, one per role, each in its own git worktree and branch.
Each role edits only the paths it owns, so pull requests rarely conflict.

| Role | Folder (worktree) | Branch | Owns |
| --- | --- | --- | --- |
| Core | `gemma4-project` | `feature/shadow-mvp` | `shadow/`, `tests/` for core code, `scripts/`, `docs/interface.md`, `.gitignore` |
| Surface + Story | `gemma4-project-surface` | `feature/shadow-surface` | `viewer/` (run report UI), `demo_site/`, `README.md`, `docs/demo-script.md`, `submission.md`, backup video |
| Proof | `gemma4-project-proof` | `feature/shadow-proof` | `evals/`, `results/`, eval tests |

## What each role does
- **Core:** the recorder, planner, runner and repair loop with local Gemma 4. Writes `docs/interface.md` first: the plan JSON schema and the run log format (steps, screenshots, repairs, timings). Everyone else builds against that file.
- **Surface:** a viewer that shows a run step by step (screenshot, intent, pass/fail, repairs), plus the demo site and its layout variants. Uses fake run logs that match `docs/interface.md` until Core's real ones exist.
- **Story:** README, demo script (what to click, what to say, timed to the minute), submission text, backup demo video. First draft early, final pass in the last hours.
- **Proof:** an eval suite of tasks times layout variants. Report task success rate, repair success rate, steps per task and time per step (`time_per_step_s`). Commit the raw results, not just the summary. Works with the fake LLM until Core runs end to end.

## Rules
1. Edit only the paths your role owns. If you need a change elsewhere, ask the user to pass it to the owning role.
2. Only Core changes `docs/interface.md`. Any change to it must be called out in the PR description.
3. Before opening a PR, run `./scripts/check.sh` (Git Bash) and paste the result into the PR.
4. Small PRs into `main`, every hour or two: `gh pr create --base main`. The user approves merges.
5. After a merge, the other roles update with `git fetch origin` then `git merge origin/main`.
6. GPU: Ollama models are shared with another project on this machine. Ask before long model runs.
7. Never commit `.env`, keys or tokens.
