# Gemma 4 project ideas (Hack or Treat, 2026-10-31)

Target category: **Best use of Gemma 4**. This project focuses on this one category only.

What makes Gemma 4 special: **open weights** (you can look inside and change it), sizes from phone-size (E2B, E4B) to 31B, local and private, image understanding, function calling, long context. The strongest entries use something only an open, local model allows.

Each idea gives: pitch, how it works, why it wins, MVP then stretch, main risk.

## G1. GLASS GEMMA: watch a model think, then possess it (suggested pick)
- **Pitch:** a live X-ray of Gemma 4. As it writes, you see which internal features light up. Then you **steer** it by adding a "concept direction" (for example "fear" or "Shakespeare") straight into its activations (the numbers flowing between its layers), dialing a slider from 0 to 1 while it talks.
- **How it works:**
  1. Load Gemma 4 with a library that exposes its internal layers.
  2. Find concept directions by comparing activations on contrasting prompts.
  3. Add the scaled direction during generation.
  4. Stream tokens plus a heatmap to a web UI.
- **Why it wins:** this is impossible with a closed API. It needs open weights, which is the deepest possible "use of Gemma".
- **MVP then stretch:** MVP is one steering slider on one concept. Stretch goals are a concept library, side-by-side steered vs. normal output, and a per-token heatmap.
- **Risk:** check first that the library supports Gemma 4's architecture. Start with E2B so it fits in GPU memory.

## G2. POCKET PROFESSOR: the big Gemma teaches the small one
- **Pitch:** the 31B model acts as teacher, generating and grading thousands of training examples for one narrow task. The E2B model is fine-tuned on them with LoRA (training a small add-on instead of the whole model). The result is a phone-size specialist that comes close to the big model on that task, running offline.
- **Why it wins:** it uses the Gemma 4 family as a family. Big and small sizes working together is a story only a multi-size open family can tell.
- **MVP then stretch:** MVP is one task, a before/after score, and the small model running locally. Stretch goals are running it on an actual phone and a chart of score against training-set size.
- **Risk:** generation and training time. Start the data pipeline in hour 2 and keep the task narrow.

## G3. HOLLOWVILLE: a town of 50 local AI villagers
- **Pitch:** a small Halloween town where 50 villagers, each a Gemma 4 agent with memory, goals and relationships, react to a rumor that "the old mill is haunted". Watch panic, skeptics and conspiracies spread in real time on a town map. Drop new events in and see how society responds.
- **Why it wins:** with a paid API, 50 agents chatting nonstop is expensive. Locally it costs nothing, and the 26B Mixture-of-Experts model (only about 4B parameters active at a time) makes it fast. It shows off open, local scale.
- **MVP then stretch:** MVP is 10 agents, a rumor spreading, and a map plus conversation log. Stretch goals are 50 agents, a relationship graph, and replay.
- **Risk:** throughput. Batch requests and update agents in turns rather than all at once.

## G4. HOME MEMORY: a private searchable diary of your camera
- **Pitch:** a home camera feeds Gemma 4, which writes a running log with timestamps ("15:02 cat jumps on counter, knocks over cup"). You ask in plain language: "when did the package arrive?", "what did the cat break today?". All video stays on your machine.
- **Why it wins:** image understanding plus long context plus privacy. This is exactly why you'd want a local model and not a cloud one.
- **MVP then stretch:** MVP is a recorded video turned into a log, then question and answer. Stretch goals are a live webcam, a daily summary, and "show me the clip" links.
- **Risk:** it misses events between sampled frames. Trigger extra captures when the image changes.

## G5. OFFLINE BRAIN: a robot with Gemma 4 as its only brain
- **Pitch:** a small wheeled robot or webcam pan-tilt rig whose entire brain is Gemma 4, with no internet. It sees through its camera and acts through function calls (`move(dir, dist_cm)`, `turn(deg)`, `look(deg)`). Ask "find the pumpkin" and it searches the room.
- **Why it wins:** a physical robot using function calling and vision, fully offline. A memorable embodied demo.
- **MVP then stretch:** MVP is a pan-tilt webcam that "looks for" a named object. Stretch goals are a wheeled base and multi-step tasks.
- **Risk:** hardware. You need parts on hand today.

## Facts checked so far
Gemma 4 was released 2026-04-02 under Apache 2.0 in four sizes: E2B, E4B, 26B MoE (about 4B active) and 31B Dense. It supports function calling and JSON output. Context is 128K on small models and 256K on large ones. Sources disagree on which sizes accept audio and video input. Early Ollama releases had tool-calling bugs. Verify anything else against the official docs before relying on it.
